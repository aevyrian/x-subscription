# 安装与维护

## 一个镜像，三个持久目录

镜像内包含 gallery-dl、任务调度器、网页接口和网站，不依赖其他业务容器。默认以 UID/GID 1000 运行。

| 容器目录 | 用途 | 备份 |
| --- | --- | --- |
| `/config` | 订阅、队列、任务历史、gallery-dl 去重库、脚本凭据哈希、收藏和配置 | 必须 |
| `/downloads` | 原始媒体与帖子 JSON | 必须 |
| `/cache` | 头像与可重建阅读索引 | 可选 |

程序文件放在镜像 `/app` 内，不能再用旧版代码目录覆盖 `/app`。下载文件保留原有 gallery-dl 结构，网站通过索引读取，整理和收藏不会移动原文件。

## 首次运行

在具有 Docker Compose 的主机上进入 `GalleryDL-X订阅`：

```sh
cp .env.example .env
# 编辑 .env，设置 LOGIN_PASSWORD
docker compose up -d --build
docker compose ps
```

默认只监听本机 `127.0.0.1:9090`。在同一主机打开 `http://127.0.0.1:9090`，输入 `.env` 中设置的密码即可进入。需要局域网访问时，将 `.env` 的 `BIND_ADDRESS` 改为主机局域网地址或 `0.0.0.0`，脚本设置中填写浏览器可访问的地址。跨公网使用已有 HTTPS 反向代理转发至 9090。

需要代理时设置 `.env` 的 `PROXY`。启动器将它传给下载进程的 HTTP/HTTPS 代理环境。已有 `config.json` 中的显式代理配置仍具有自己的优先级，迁移时请检查。实际代理口令只放在本机 `.env` 或持久配置，不提交 Git。

首次启动自动生成 `/config/config.json`，后续启动保留原配置。没有登录密码时服务直接拒绝启动。镜像中的 gallery-dl 版本固定，升级引擎应修改版本并重新构建验证。

## 接入 X 登录状态

登录网站，在原有管理区域的 X 登录状态功能中上传本人授权的 Netscape 格式 cookies.txt。服务只保留 X/Twitter 域对应记录；脚本不读取浏览器 X Cookie，不接收这份文件。

先用一条有权下载的帖子验证登录与媒体，再尝试博主下载。队列接收成功不代表 X 登录有效，也不代表下载完成。限流、失效登录和网络错误应查看网站任务详情。

## 安装 ScriptCat 脚本

1. 打开网站“下载与连接”页，点击“安装 / 下载 ScriptCat 脚本”。原文件在 `integration/xarchive.user.js`。
2. 在 ScriptCat 确认安装；脚本只匹配 X/Twitter 页面。
3. 在网站生成一个连接凭据，只显示一次。
4. 打开 X，点击右下角小圆钮，再进入“连接设置”。填写网站根地址和刚生成的连接凭据。
5. 按 ScriptCat 提示允许访问你自己的网站地址，然后尝试推送一位博主。

凭据只保存在脚本的独立存储中；服务端仅保存哈希。它可以提交下载或订阅、读取任务与归档状态，不能用于登录网站、上传 Cookie、撤销其他连接或删除媒体。需要停用时在网站撤销对应连接。

`@connect *` 用于支持用户自己的 NAS 地址和域名，实际网络请求仅发往设置中保存的根地址。可在安装前将 `*` 收窄为自己的域名或 IP。脚本没有遥测，也不向 GitHub 发送下载数据。

ScriptCat API 依据[官方 API 文档](https://docs.scriptcat.org/docs/dev/api/)实现。当前自动化覆盖了脚本的本地模拟环境；真实 X 页面与实际 ScriptCat 扩展权限仍需要联调，不能以模拟测试替代。

## 迁移现有部署

先在独立目录试运行，勿直接替换正在工作的 Reader/gallerydl。停止旧下载器后，备份原配置与媒体，再将其副本分别挂载到 `/config` 和 `/downloads`。Reader 原来的 `/data` 目录在新容器统一为 `/downloads`。

原有 `subscriptions.json`、`.jobs.json`、`archive.sqlite`、`.reader-favorites.json`、cookies 目录和 `.last_*` / `.next_*` 状态需要一起保留。原有配置中 `/config` 和 `/downloads` 的容器路径可继续使用。外部绑定目录需要事先允许 UID/GID 1000 读写；不要对整个 NAS 执行递归改权限。

不要让新旧下载器同时写同一去重库和媒体目录。先核对博主数量、历史任务、收藏、图片和视频读取，再切换入口。原服务备份和旧镜像在验证前保留。

## 更新、停止和恢复

```sh
docker compose up -d --build  # 更新程序，保留持久卷
docker compose logs --tail=100
docker compose stop         # 停止，不删除数据
```

健康检查验证网站 `/login`；启动器还会监控 Reader 与调度器进程，任一个退出时容器退出，由重启策略恢复。它不能证明 X 登录有效或下载成功。

备份时先停止容器，复制 `/config` 和 `/downloads`。恢复时使用兼容版本镜像挂载备份副本验证。不要使用 `docker compose down -v`，该命令会删除命名卷。
